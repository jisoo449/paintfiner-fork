Dockerfile:2
--------------------

   2 | >>> From node:20 AS build
   3 |     WORKDIR /app

## 작업 상세 내용
1. 디스크 공간 확보:  
    - **Docker 리소스 정리**: 사용하지 않는 Docker 리소스(컨테이너, 이미지, 볼륨, 네트워크 등)를 제거하여 공간을 확보할 수 있습니다. 다음 명령어를 실행하세요:  
        ```
        docker system prune -a --volumes
        ```
    - **디스크 사용량 확인**: 다음 명령어를 사용하여 시스템의 디스크 사용량을 확인할 수 있습니다:  
        ``` 
        df -h
        ```
    - **불필요한 파일 제거** : 가능하다면, 불필요한 파일을 제거하거나 다른 저장 장치로 이동시키세요.  

2. 디스크 공간 증설:  
    - 가상화 환경에서 작업 중이라면, 가상 머신이나 컨테이너에 할당된 디스크 공간을 증설하는 것을 고려하세요.  
    - 클라우드 기반 CI/CD 플랫폼을 사용하는 경우, 더 많은 스토리지가 포함된 상위 플랜으로 업그레이드하거나 추가 스토리지 볼륨을 연결할 수 있습니다.  

3. 멀티스테이지 빌드 최적화:  
    - Dockerfile이 최적화되어 있고 불필요하게 큰 레이어를 생성하지 않는지 확인하세요. FROM node:20 AS build 줄은 멀티스테이지 빌드를 사용하고 있다는 의미로, 이미 좋은 방법이지만, 불필요한 파일을 이미지에 복사하지 않도록 주의해야 합니다.  

4. 빌드 컨텍스트 확인:
    - 빌드 컨텍스트에 너무 많은 파일이나 큰 파일을 복사하는 경우도 있습니다. .dockerignore 파일을 사용해 빌드에 필요 없는 파일을 제외하고 있는지 확인하세요.  

5. 다른 빌드 환경 시도:  
    - 문제가 계속 발생하고 CI/CD 서비스를 사용 중이라면, 디스크 공간이 더 많은 다른 러너나 에이전트를 사용하는 것을 고려해 보세요.

## 방법2. 도커 컴포즈 파일 수정
디스크 공간 부족 문제를 해결하기 위해 Docker Compose 파일에서 몇 가지 설정을 수정할 수 있습니다. 대표적인 방법은 다음과 같습니다:

### 1. **Docker Compose에서 볼륨 설정을 조정하기**

Docker Compose 파일에서 컨테이너가 사용하는 볼륨을 호스트의 특정 디렉토리로 매핑하여, 디스크 공간 부족 문제를 완화할 수 있습니다. 예를 들어, 데이터베이스 컨테이너에서 데이터를 로컬 디스크의 특정 경로에 저장하도록 설정할 수 있습니다.

```yaml
version: '3.8'
services:
  database:
    image: postgres
    volumes:
      - /host/path/to/data:/var/lib/postgresql/data
```

위 설정은 데이터베이스 컨테이너의 데이터 디렉토리(`/var/lib/postgresql/data`)를 호스트의 `/host/path/to/data` 디렉토리에 매핑합니다. 이렇게 하면 Docker 컨테이너 내부의 데이터가 호스트의 디스크에 직접 저장되므로, Docker가 사용하는 디스크 공간을 줄일 수 있습니다.

### 2. **Docker Compose에서 로컬 캐시 사용 줄이기**

Docker Compose 빌드 시 캐시 사용을 최소화하거나 끄면 불필요한 캐시 데이터가 쌓이지 않아 디스크 공간을 절약할 수 있습니다. Docker Compose 파일에 `build` 옵션을 추가하여 캐시를 줄이도록 설정할 수 있습니다.

```yaml
version: '3.8'
services:
  web:
    build:
      context: .
      args:
        - DOCKER_BUILDKIT=1
        - BUILDKIT_INLINE_CACHE=0
```

### 3. **임시 컨테이너와 볼륨 자동 삭제 설정**

Docker Compose에서 컨테이너가 종료될 때 볼륨이나 컨테이너를 자동으로 삭제하도록 설정하여 디스크 공간을 절약할 수 있습니다.

```yaml
version: '3.8'
services:
  temporary_service:
    image: some_image
    volumes:
      - some_volume:/path/in/container
    restart: no
    command: some_command
    deploy:
      mode: replicated
      replicas: 1
      placement:
        constraints:
          - node.role == manager
    configs:
      - source: my_config
        target: /etc/config
    tmpfs: /run
```

여기서 `tmpfs` 설정은 특정 디렉토리를 메모리에서 운영하도록 하여 디스크 사용을 줄입니다.

### 4. **Docker의 기본 디스크 사용 제한 설정**

Docker Compose에서 기본적으로 사용할 수 있는 디스크 용량을 제한할 수 있는 설정은 없지만, Docker 데몬 설정에서 기본적으로 사용 가능한 디스크 용량을 제한하는 방법이 있습니다.

```yaml
version: '3.8'
services:
  myservice:
    image: myimage
    deploy:
      resources:
        limits:
          disk: 1g  # 1GB로 디스크 사용을 제한
```

이러한 설정을 적용하면 Docker가 사용할 수 있는 디스크 공간을 제한할 수 있으며, 디스크 공간 부족 문제를 완화할 수 있습니다.

### 5. **로컬에서 Docker 시스템 청소**

디스크 공간 부족 문제가 계속 발생할 경우, Docker 시스템을 청소하여 불필요한 이미지, 컨테이너, 네트워크 및 볼륨을 제거할 수 있습니다.

```bash
docker system prune -a
```

이 명령어는 사용하지 않는 모든 도커 객체를 삭제하여 공간을 확보합니다.

### 요약
Docker Compose 파일에서 디스크 공간 문제를 직접 해결할 수 있는 방법은 제한적이지만, 볼륨 매핑, 캐시 설정, 자동 삭제 설정 등을 통해 간접적으로 문제를 완화할 수 있습니다. 가장 효과적인 방법은 불필요한 도커 리소스를 정기적으로 청소하는 것입니다.

## 방법3. github-action.yml 파일 설정
GitHub Actions의 YAML 파일에서 디스크 공간 부족 문제를 해결하기 위해 몇 가지 조치를 추가할 수 있습니다. 특히, CI/CD 파이프라인에서 Docker 이미지를 빌드하거나 테스트를 실행할 때 디스크 공간을 절약하는 것이 중요합니다. 다음은 그런 경우에 유용한 설정들입니다.

### 1. **`actions/cache`를 사용한 캐싱 관리**

GitHub Actions에서 `actions/cache`를 사용해 의존성 캐싱을 관리하면, 빌드 속도를 높이면서도 불필요한 디스크 사용을 줄일 수 있습니다. Docker 레이어 캐시를 사용하는 방법도 있습니다.

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Cache Docker layers
        uses: actions/cache@v3
        with:
          path: /tmp/.buildx-cache
          key: ${{ runner.os }}-docker-${{ github.sha }}
          restore-keys: |
            ${{ runner.os }}-docker-

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Build and push Docker image
        uses: docker/build-push-action@v5
        with:
          context: .
          push: false
          tags: user/app:latest
          cache-from: type=local,src=/tmp/.buildx-cache
          cache-to: type=local,dest=/tmp/.buildx-cache
```

### 2. **빌드 후 리소스 정리**

빌드 후 불필요한 Docker 이미지나 컨테이너, 네트워크, 볼륨 등을 정리하면 디스크 사용량을 줄일 수 있습니다.

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Build Docker image
        run: docker build -t my-image .

      # 빌드가 끝난 후 모든 사용하지 않는 Docker 리소스 삭제
      - name: Clean up Docker
        run: docker system prune -af
```

### 3. **디스크 공간 확인 및 경고**

빌드 중 디스크 사용량을 모니터링하고, 디스크 공간이 부족할 경우 경고 메시지를 출력하도록 설정할 수 있습니다.

```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Check disk space before build
        run: df -h

      - uses: actions/checkout@v3

      - name: Build Docker image
        run: docker build -t my-image .

      - name: Check disk space after build
        run: df -h
```

### 4. **매트릭스 전략으로 테스트 분산**

테스트가 많아서 디스크 공간을 많이 차지하는 경우, GitHub Actions의 매트릭스 전략을 사용해 작업을 분산시키고, 병렬로 실행하면 디스크 사용량을 줄일 수 있습니다.

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node-version: [12, 14, 16]
    steps:
      - uses: actions/checkout@v3
      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: ${{ matrix.node-version }}
      
      - run: npm install
      - run: npm test
```

### 5. **Docker 레이어 캐시 최적화**

Docker 이미지를 빌드할 때, `.dockerignore` 파일을 잘 관리하여 불필요한 파일이 Docker 컨텍스트에 포함되지 않도록 하고, 빌드의 각 단계가 가능한 한 적은 양의 데이터를 처리하도록 최적화합니다.

```yaml
# Dockerfile에서의 최적화 예시
FROM node:14
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install --production
COPY . .
CMD ["node", "index.js"]
```

위와 같이 최적화된 `Dockerfile`을 사용하면, 빌드 프로세스가 더 효율적이 되며, 이는 GitHub Actions에서 사용하는 디스크 공간을 줄이는 데 도움을 줍니다.

### 요약
- `actions/cache`를 사용해 Docker 레이어나 의존성의 캐싱을 관리하여 디스크 공간을 절약할 수 있습니다.
- 빌드 후 Docker 리소스를 정리해 디스크 공간을 확보합니다.
- 작업 전에 디스크 사용량을 체크해 경고를 출력할 수 있습니다.
- 매트릭스 전략을 사용해 작업을 분산시켜 병렬로 실행합니다.
- Docker 이미지를 최적화하여 빌드 프로세스에서 불필요한 파일이 포함되지 않도록 합니다.

이와 같은 방법들을 적용하면 GitHub Actions에서 디스크 공간 부족 문제를 완화할 수 있습니다.
