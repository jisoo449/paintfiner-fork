## 문제  설명
### 1. then 과 catch 둘 다 실행됨
```
  const fetchData = async (code) => {
    await getJwtFromOauth(code).then(res=>{
      const accessToken = res.data.accessToken;
      const refreshToken = res.data.refreshToken;
      setAccessToken(accessToken);
      setCookie('refreshToken', refreshToken, {expires:1});
    }).catch(error=>{console.log("에러발생", error)})
  }
```
위 코드를 useEffect 안에서 실행 시 then 과 catch 안의 내용 모두가 실행되는 것을 확인하였다.  
~~이는 getJwtFromOauth 함수가 반환하는 프로미스가 rejected되었을 때도 catch 블록이 실행되기 때문이다.~~ *가 아니었습니다!*  
이는 then 절 내에서 오류가 발생했기 때문이다.   
`setCookie('refreshToken', refreshToken, {expires:1});` 부분의 expires 문법에 오류가 있었다. 이를 올바르게 해결하기 위해서는   
`{ expires: new Date(Date.now() + 86400 * 1000) }`  
로 수정 해 주어야 한다.  

## 2. 상태 저장 안됨
로그인, 비로그인 시 나타나는 형태가 다른 컴포넌트가 있다.

이 컴포넌트는 다음과 같은 코드를 따른다.
```
    if (user.state){//로그인 상태
        return(
            <div className={styles.icon_box}>
                <a className={styles.icon_string} href='/forum'> 포럼 </a>
                <a className={styles.icon_string} href='/mypalette'> 마이팔레트 </a>
                <a className={styles.icon_string} onClick={logout()} href='/'> 로그아웃 </a>
            </div>
            )
    }
    else{
        return(
            <div className={styles.icon_box}>
                <a className={styles.icon_string} href='/login'> 로그인 </a>
                <a className={styles.icon_string} href='/forum'> 포럼 </a>
                <a className={styles.icon_string} href='/mypalette'> 마이팔레트 </a>
            </div>
        )
    }
```
if문이 실행될 때 커스텀 훅에서 가져온 logout이 바로 실행된다. 이로 인해 이전 단계에서 저장한 모든 값들이 삭제가 된다. 따라서 해당 부분을 onClick 이벤트가 발생할 시 실행하는 함수로 빼 주어야 한다.

## 3. SSL 통신

크롬 80버(2020-02-04 Release)부터 http 사이트에서 쿠키가 제한된다. 따라서 ssl 인증서를 등록해야 한다.  
1. chocolately 설치([공식문서](https://docs.chocolatey.org/en-us/choco/setup#more-install-options))
   ``` cmd
   @"%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe" -NoProfile -InputFormat None -ExecutionPolicy Bypass -Command "[System.Net.ServicePointManager]::SecurityProtocol = 3072; iex ((New-Object System.Net.WebClient).DownloadString('https://community.chocolatey.org/install.ps1'))" && SET "PATH=%PATH%;%ALLUSERSPROFILE%\chocolatey\bin"
   ```
2. 리액트 경로 안에 mkcert 설치
   ```
   choco install mkcert
   mkcert -install
   ```
3. 인증서 설정
   ```
   mkcert -key-file ./key.pem -cert-file cert.pem "localhost"
   ```

## 문제 설명
쿠키는 SSL 통신이 되는 브라우저에서 저장할 수 있다. 따라서 배포 및 개발환경의 SSL로의 전환이 필요하다.  
또한, SSL 통신을 하는 브라우저는 SSL 통신하는 브라우저끼리 통신이 가능하다.  
만약 프론트는 HTTPS로 통신하고, 백엔드는 HTTP로 통신한다면 이는 통신 규약에 위배되므로 제대로 된 통신이 되지 않을 것이다.  
따라서 다음과 같은 설정을 통해 문제를 해결해야 한다.  

## 해결
### 1. 프론트 SSL 통신 설정
#### 1.1. 배포 환경
배포 환경에서는 ACM을 사용해 HTTPS 통신이 가능하도록 하였다.

#### 1.2 개발 환경
개발 환경에서는 로컬로 임시 SSL 인증서를 발급받고, package.json 파일에서 start를 HTTPS로 하도록 set 해 준다.

### 2. 백엔드와의 SSL 통신 설정
백엔드 통신 자체를 HTTPS 로 하면 좋겠지만, 이는 꽤나 어려운 작업이 된다. 따라서 CORS Config 파일에서 https와 통신하도록 설정을 해 준다.   
또한 프론트에서는 package.json 파일에 proxy 서버를 다음과 같이 추가 해 주어야 한다.
```
"proxy":"백엔드주소:통신포트"
```

### 3. 카카오 redirect uri 설정
프론트의 .env 파일, 백엔드의 application_key.properties 파일, 그리고 카카오 dev에서 redirect_uri를 `https://프론트도메인/로그인/핸들러/경로` 로 설정 해 주어야 한다.
