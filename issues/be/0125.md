## 1. Description
더욱 손쉬운 관리를 위하여 AWS 서비스를 사용한 서버리스 배포 방식을 채택하려 한다.  
참고한 구조는 다음과 같다.  
![image](https://github.com/user-attachments/assets/352f09a5-abc8-4f0b-982a-dd724ec8cc5c)  
위 구조와 유사하게 백엔드는 AWS Codebuild, AWS CodePipeline, AWS Elastic Beanstalk를 사용하고, 프론트엔드는 Amplify를 사용하여 배포할 예정이다.

## 2. 배포 방법
AWS에서 제공하는 서버리스 서비스를 사용해 백엔드를 배포하는 방법은 아래와 같은 순서로 나뉜다.

1. CodeBuild 생성
2. ElasticBeanstalk 생성
3. CodePipeline 생성

### 2.1. CodeBuild 생성
AWS 코드빌드를 생성하는 방법은 다음과 같다.
1. CodeBuild 콘솔에서 빌드 프로젝트 생성 페이지로 이동
2. 프로젝트 이름 설정. 백엔드이므로 퍼블릭 빌드 액세스 활성화는 체크하지 않는다.  
   ![image](https://github.com/user-attachments/assets/413dd8cc-ab98-4750-ab8d-9303d80e1942)  
3. 소스 공급자 설정  
   깃헙의 코드를 사용할 예정이므로 깃헙 코드를 등록한다.     
   ![image](https://github.com/user-attachments/assets/c80a057b-454e-4708-b864-0cd1f33bfd20)
4. 기본 소스 Webhook 이벤트  
   웹훅을 생성하여 푸시 발생 시 빌드가 진행되도록 한다. 
   ![image](https://github.com/user-attachments/assets/3e1aab8f-4eb3-4c30-99d9-1c8a008a8ed2)
5. 환경은 Amazon으로 선택
6. 빌드스펙 편집기로 생성
   ```yaml
   version: 0.2
   
   phases:
     install:
       commands:
         - echo "Installing dependencies"
         - yum update -y
         - echo "Downloading application_key.properties from S3"
         - aws s3 cp s3://paintfinder-application-key/application_key.properties ./src/main/resources/  # 리소스 디렉토리에 저장
         - echo "Downloading and installing Gradle"
         - wget https://services.gradle.org/distributions/gradle-7.5-bin.zip  # Gradle 버전 확인 후 필요에 따라 변경
         - unzip gradle-7.5-bin.zip
         - mv gradle-7.5 /opt/gradle
         - export PATH=$PATH:/opt/gradle/bin  # 환경 변수에 Gradle 추가
     pre_build:
       commands:
         - echo "Cleaning the project"
         - gradle clean
         - echo "Listing files in current directory:"
         - ls -R
     build:
       commands:
         - echo "Building the project with Gradle"
         - gradle build --parallel
         - cp build/libs/*.jar ./application.jar
     post_build:
       commands:
         - echo "Build completed"
   artifacts:
     files:
       - application.jar  # 빌드된 JAR 파일을 아티팩트로 저장
   cache:
     paths:
       - '/root/.gradle/**/*'
   ```

### 2.2. AWS Elastic Beanstalk 생성
백엔드 서버를 띄우기 위한 AWS Elastic Beanstalk 환경을 생성하라.  
AWS Elastic Beanstalk 콘솔에 들어가서 애플리케이션을 생성한 뒤 환경을 생성하라.  
1. 애플리케이션 생성
   ![image](https://github.com/user-attachments/assets/bc7bf3ba-8a18-433e-a123-1f418efe2dbb)  
   ![image](https://github.com/user-attachments/assets/dea04d35-b411-4d21-a334-a1b0aa04fc7a)  
2. 생성한 애플리케이션 클릭 후 새 환경 생성  
   ![image](https://github.com/user-attachments/assets/39d2e71e-d14c-4486-9745-85b30867dfbb)  
3. 1단계 환경 구성에서는 플랫폼 유형만 사용하는 언어/환경으로 설정  
    Java를 사용하므로 Java를 선택한다.  
    ![image](https://github.com/user-attachments/assets/fc78a869-76c5-4c76-a5bb-e0ca31ab755f)  
4. 서비스 역할 선택  
    이전에 생성한 역할 및 EC2 키페어가 있으므로 해당 객체를 선택한다.  
5. 3단계 네트워킹 선택  
    VPC는 현재 생성된 기본 VPC를 선택하자.  
    인스턴스 및 DB 인스턴스 서브넷은 RDS가 생성된 곳을 선택하라.  
6. 4단계 인스턴스 선택  
    루트볼륨 유형은 범용3(SSD), IMDSv1 비활성화 설정 체크, 이외의 설정은 건드리지 않는다.  
    ![image](https://github.com/user-attachments/assets/da8f0e74-2ce6-40a3-9753-b6f799915b6c)  
    ![image](https://github.com/user-attachments/assets/981f0915-d515-4198-a1ec-adc21889c440)
7. 5단계 업데이트, 모니터링 및 로깅 구성  
    맨 마지막 환경 속성에 키 SERVER_PORT, 값 5000 추가  
    ![image](https://github.com/user-attachments/assets/c92e2149-8e70-4be3-92c3-89ad7335e499)

위 단계를 거치면 스팟 인스턴스를 제공하는 엘라스틱 빈스토크 환경이 생성된다.
