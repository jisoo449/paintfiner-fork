## 본문

## 설명
백엔드의 빌드를 AWS CodeBuild, S3를 통해 하려 하였다. 이 때 application_key.properties 파일을 S3버킷에 저장한 후 코드빌드의 BuildSpec에 빌드 S3에 저장된 application_key.properties를 설치하게 하려 했으나, Elastic Beanstalk에 배포 및 실행될 때 다음과 같은 오류가 발생하였다.
```
Caused by: java.io.FileNotFoundException: class path resource [application_key.properties] cannot be opened because it does not exist
```

## 문제 원인
Spring Boot 프로젝트에서는 application_key.properties 파일을 열려 하였으나, build spec에 작성된 yaml에서는 application_key.yaml 파일을 다운로드 받도록 하였다.  
따라서 S3 객체에 접근하여 이름을 변경하고, CodeBuild의 프로젝트에 들어가 build spec을 yaml에서 properites로 수정 해 주었다.

## 해결방법
application_key.properties 파일과 같은 민감 정보를 JAR 파일에 저장하는 것은 위험할 수 있다. 다음과 같은 방법들이 대안이 될 수 있다.

1. 환경 변수 또는 Elastic Beanstalk 환경 속성:
    - 가장 간단하고 보안 위험이 적음.
    - 서버에 접속하여 echo 명령어로 해당 키들을 확인할 수 있으므로 추천하는 방식은 아니다.
2. AWS Secrets Manager 또는 AWS SSM Parameter Store 사용:
    - 민감한 정보가 많고, 고도의 보안이 필요한 경우 적합.
    - Spring Boot 애플리케이션에서 AWS SDK 또는 Spring Cloud AWS를 통해 비밀을 읽어옵니다.
      ```properties
      <dependency>
          <groupId>org.springframework.cloud</groupId>
          <artifactId>spring-cloud-starter-aws-secrets-manager-config</artifactId>
      </dependency>
      ```
      ```JAVA
      @Value("${application.key}")
      private String applicationKey;
      ```

3. 파일 외부화 (S3):
    - S3에서 관리하는 방식도 유용하지만, 파일 다운로드 시 네트워크 연결이 필요하므로 환경에 따라 주의.
      ```JAVA
      import org.springframework.core.io.ClassPathResource;
      import java.io.InputStream;
      import java.util.Properties;
      
      public class AppConfig {
          public static Properties loadProperties(String filePath) throws Exception {
              InputStream input = new ClassPathResource(filePath).getInputStream();
              Properties properties = new Properties();
              properties.load(input);
              return properties;
          }
      }
      ```
하지만 가격적인 문제로 인해 jar에 한꺼번에 build 하는 것을 선택하였다.

현재 @Value 어노테이션을 통해 application_key.properties 파일을 가져오고 있다. @Value 어노테이션은 설정파일(properties, yaml 등)에 설정한 내용을 주입시키는 어노테이션이다. 
우리는 S3에서 application_key.properties에서 파일을 받아 빈으로 등록하고, 의존성 주입으로 사용하려 한다.
